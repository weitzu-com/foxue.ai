## 第一性原理结论

SEO 的底层不是“有没有 title”，而是四件事：

1. 搜索引擎能否稳定发现页面
2. 每个 URL 是否有唯一、可信、可自证的身份信号
3. 页面主题是否被 title / description / structured data 正确表达
4. 生产环境是否能证明“线上就是你以为部署的那份代码”

按这四条检查，`www.foxue.ai` 当前不是单点问题，而是“生产部署落后于仓库中的 SEO 修复”。

仓库内生产核验脚本对现网执行后：

- 88 项通过
- 104 项失败

## 根因判断

从第一性原理看，这次不是“页面 SEO 细节做得不够多”，而是：

1. 生产部署明显落后于当前仓库中的 SEO 修复
2. 主题 Hub 路由没有真正上线，导致内容入口层断裂
3. 机器可读文件、页面 metadata、JSON-LD、发布指纹没有作为一个整体一起交付
4. `ai.txt` 的权利边界在代码层也还存在一处原则冲突，需要上线前先收紧

换句话说，当前最大问题不是“再写几个 meta tag”，而是“把已经存在的 SEO 基线完整、可验证地送上生产”。

## 优先级建议

### P0

- 先恢复 `/gainian` 与概念子页的生产可访问性
- 同时确认这些页面进入 sitemap

### P1

- 部署当前 `robots.ts`、页面 metadata、页面级 JSON-LD、`llms.txt`、`ai.txt`、`/api/health`
- 部署后立即重新跑生产核验脚本

### P2

- 收紧 `ai-policy` 中“training datasets” 的表述，改为“仅在底层来源权利明确允许时才可训练使用”，或者直接去掉 blanket permission
- 再做一次现网复核，确认 AI 策略与透明页权利表述不冲突

## 建议的验收标准

部署完成后，至少满足以下条件：

- `node scripts/verify-google-integrations.mjs https://www.foxue.ai` 全绿
- `/gainian` 与概念子页全部 200 且进入 sitemap
- `robots.txt` 只声明 `https://www.foxue.ai/sitemap-index.xml`
- 关键页 title / description / canonical / `og:url` 全部与页面职责一致
- 关键页页面级 JSON-LD 全部存在
- `llms.txt` 与 `ai.txt` 完全统一到 `https://www.foxue.ai`
- `/api/health` 带 `noindex, nofollow` 与部署指纹

## 结论

截至 2026-08-20，`www.foxue.ai` 的 SEO 主要问题不是“内容不够多”，而是“生产输出没有稳定表达当前站点结构与页面身份”，并且存在明显的上线断层。

如果只排一个最关键动作，不是继续做新页面，而是：

先把当前分支里已经存在的 SEO 修复完整上线，并用生产核验脚本闭环验证。
