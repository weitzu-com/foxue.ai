# foxue.ai 域名与账户继任治理

## 目的与边界

域名是读者找到服务的稳定入口，却不是经藏本身。本文件定义把 `foxue.ai`、`www.foxue.ai` 与 `canon.foxue.ai` 的控制权从单一人员和单一供应商中拆出的最低治理要求。它不能保证任何注册商或支付方式在未来一百年持续存在；目标是让续费、迁移、故障切换与继任都能被执行和审计。

本文件只记录流程与证据要求；绝不记录密码、恢复码、API 令牌、账户编号、付款信息或个人身份材料。

## 不可变原则

1. 域名失效不能使经藏消失：源码、发布清单、R2 对象键与离线恢复包必须可在新域名或无域名环境恢复。
2. 域名迁移不能改变经文稳定定位符：旧网址至少保留可导出的映射表，并在可行时做长期 301 重定向。
3. 没有单一人员能永久阻断续费、DNS 迁移或恢复：至少两位独立受托维护者应能在不依赖原作者的情况下完成流程。
4. 不能以“已自动续费”代替证据：每次检查必须记录到期日、注册商状态、DNSSEC/锁定状态、受托人确认与下一次检查时间。

## 最低控制面

| 对象 | 最低要求 | 可审计证据 | 失效时的恢复路径 |
|---|---|---|---|
| `foxue.ai` 注册 | 自动续费、有效付款冗余、注册锁与支持 DNSSEC 的注册商 | 不含敏感数据的年度核对记录和到期日 | 由两名受托维护者按离线继任封套迁移至新注册商 |
| DNS Zone | 导出为可版本化的公开/脱敏配置；变更双人复核 | 带日期的 Zone 导出校验和、变更日志 | 在独立 DNS 提供商重建；仍可控制旧权威区时，先在旧区把记录 TTL 降至切换窗口以下并等待既有缓存到期，再切换委派；旧区不可控时，按缓存的委派/记录 TTL 预留降级窗口并公开迁移状态 |
| Cloudflare / Vercel | 最小权限、至少两名组织管理员、令牌轮换 | 管理员名册哈希、权限审计日期、部署/恢复演练记录 | 从 Git、Release 与恢复手册迁移到替代提供商 |
| 支付与法定责任 | 不依赖单张银行卡或单一自然人；明确实体/受托方 | 不公开的受托文件索引与年度确认 | 由指定继任人执行续费、迁移或保护性转移 |

## 时间表与责任分离

| 节奏 | 必做事项 | 通过条件 |
|---|---|---|
| 每月 | 自动检测 HTTP、TLS 证书到期、DNS 解析、域名到期窗口 | 失败告警送达两名维护者；监控不包含凭据 |
| 每季度 | 导出 DNS、检查注册锁/DNSSEC、核对 R2 与公开恢复入口 | 脱敏导出与哈希进入长期审计日志 |
| 每年 | 两名独立继任维护者完成一次无原作者参与的恢复与域名迁移桌面演练 | 记录演练日期、参与角色、用时、发现的问题和关闭证据 |
| 注册到期前 180/90/30 天 | 多渠道续费提醒与人工确认 | 两名受托人确认有效续费状态，或启动迁移预案 |

## 域名不可用时的操作顺序

1. 保持 GitHub Release、Software Heritage、R2 与离线介质的完整性检查，不以恢复网站为由修改历史发行。
2. 在独立 DNS/注册商创建替代域名和 DNS Zone，使用 [`RECOVERY.md`](./RECOVERY.md) 从零恢复网站与只读经藏边缘层。
3. 发布可签名的旧域名—新域名映射说明；旧域仍可控时设置 301，失控时在 GitHub、Release、机构镜像和社群公告中发布迁移证明。
4. 对外说明迁移事实、日期与校验值；不得把替代域名描述为原域名仍持续可用。

## 年度证据包

年度证据包应仅包含：日期、域名状态、到期窗口、脱敏 DNS 导出哈希、DNSSEC/注册锁状态、受托角色确认、最近恢复演练报告哈希、公开健康检查结果和待办事项。它应进入至少两个独立保存域，并与本仓库的不可变 Release 互相引用。

在下列证据全部存在前，foxue.ai 只能诚实地称为“已建立域名继任流程”，不能称为“已保证域名一百年续费”：连续多年演练记录、独立受托人实际参与、隔离的付款/法定安排，以及至少一次不依赖原维护者的成功迁移或恢复演练。
