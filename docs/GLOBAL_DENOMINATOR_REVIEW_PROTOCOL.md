# foxue.ai 全球佛经作品分母独立复核协议

版本：0.1.0

状态：公开草案；尚不具备发布全球覆盖率的条件

适用数据：GBCR v6.18.0

## 1. 目的

foxue.ai 的长期目标是收录全球 99% 以上的佛经，但百分比只有在分母有限、版本化、可复算且可被反驳时才有意义。本协议规定如何把目录记录、译本、版本见证、卷册、写本残片和暂定作品，审校为不重复的作品级分母。

本协议不判断宗教信仰真伪，也不把“传统正典地位”自动等同于“历史上的佛陀逐字亲说”。它只建立一套公开、可追溯的范围与作品身份治理程序。

## 2. 不可违反的计数原则

1. Work、Expression、Witness、卷、段和物理文件是不同实体，不得直接相加。
2. 机器规则与 AI 只能整理、检索和排序证据，不能计作独立复核者。
3. 未决候选暂按一个可能作品计入保守分母，且不进入任何覆盖分子。
4. 可能重复的记录在双重复核前不得自动合并；可能排除的记录在裁决前不得静默删除。
5. 尚未审计的外部来源空白使全球百分比保持 `null`，不得记为 0 或忽略。
6. 编目、完整原文、中文译文、权利可发布和质量通过分别计算，不发布加权“总覆盖率”。

## 4. 复核者资格与独立性

每条范围裁决与作品身份裁决分别需要至少两名自然人独立完成。复核者必须：

- 公开具名，提供可核验的学术、语言、目录学、版本学或传统传承能力说明；
- 披露与 foxue.ai、来源项目、版本、译文、出版者、作者、另一复核者及相关机构的关系；
- 能直接核对相关语言或明确说明依赖的可靠转写、译文与目录工具；
- 提交公开证据、最强支持理由与最强反证；
- 通过签名 Git 历史或同等可验证签名承担责任。

同一机构的两人原则上不构成充分独立；确需配对时，必须公开说明报告线、资助、共同出版和判断过程如何相互独立。v0.1 自动共识路径采取更严格的机器门：只有决定发生时机构声明不同的两名复核者才会形成自动候选共识；同机构例外必须经过公开协议升级和人工仲裁，不能靠自由文本绕过。复核者更换机构或纠正机构写法时追加版本化机构记录，每项决定仍保存当时的机构快照。AI 生成内容可以作为检索线索，但 AI 不能署名、不能满足双人门槛，也不能作最终裁决。

## 5. 每个任务的三条审校线

### 5.1 范围线

允许结论：

- `include_strict_sutra`：按当前严格佛经范围纳入；
- `exclude_strict_sutra`：不计入严格佛经范围，但可作为律、论、注疏、史传、仪轨或参考文献保留；
- `scope_uncertain`：证据不足，继续按可能作品进入保守分母。

复核必须说明传统归属、正典分区、文本自称、目录分类、疑伪状态、合集/单品关系以及采用的“佛经”口径。

### 5.2 作品身份线

允许结论：

- `same_work`：不同记录是同一作品的表达或见证；
- `distinct_work`：题名、结构、范围或内容足以证明为不同作品；
- `text_family_only`：只可确认文本家族关系，不能合并为同一作品；
- `identity_uncertain`：证据不足；
- `not_applicable`：该任务无需身份聚类。

复核必须比较首尾、章节结构、内容顺序、人物地点、显著增删、题名沿革、译者/编者责任、卷数、目录号、版本链和可定位原文。题名相似、目录号相邻或现成数据库链接本身不足以证明同一作品。

### 5.3 来源与范围线

允许结论：

- `source_supported`：来源身份、底本、完整性与文本范围均有可公开核对的证据；
- `source_rejected`：来源归属、底本或范围声明与证据冲突；
- `source_uncertain`：来源或范围证据不足，继续保持未决。

复核必须定位目录号、版本、卷页、稳定段落或持久链接，并区分整部、合集组件、节译、版本见证、残片和引用。工作台预填内容只用于定位；复核者必须在“人工核验补充”后写入自己的核验结果，原样提交机器预填不会通过摄取门。

## 6. 提交流程

1. 从公开队列选择一个 `queueId`，优先处理 P0、P1。
2. 阅读该项的当前规则分类、来源表达、目录链接和审计理由。
3. 在不知道或不依赖另一位复核者结论的前提下独立核对证据。
4. 使用 GitHub 的“全球分母独立复核”表单提交意见，并明确机构、独立完成声明和来源与范围结论。
5. `global-denominator-review-intake` 工作流把 Issue 正文视为不可信输入：核对仓库、作者账户、队列 ID、字段唯一性、三条允许结论、人工补充、六项声明与 HTTPS 证据；Bot、篡改、缺项或原样机器预填立即失败。
6. 通过自动门只会生成 90 天临时候选制品。候选状态明确为“不计作真人决定”，不会写仓库、不会修改账本、不会改变分母。
7. 维护者核验提交者身份、能力、机构、证据、权利和利益冲突后，使用 `scripts/global-review-intake.mjs accept-candidate` 预演；正式 `--write` 会通过 GitHub API 实时读取当前仍开放的 Issue，并与当前队列重新生成候选，不能只凭旧制品、本地事件或可被重算的候选哈希验收。若 Issue 已关闭，或正文、标题、作者等签名内容已变化，必须拒绝旧候选；仅由评论、标签引起的 `updated_at` 变化不误伤未改正文。另一名维护者通过受保护 Pull Request 复核后，才可写入，同时归档原始 Issue、正文哈希与验收身份。
8. 一份合格提交规范化为同一自然人的范围、作品身份、来源与范围三条决定；它仍不满足双人门槛。
9. 两位不同机构复核者一致时进入候选共识；有实质分歧时保持未决，并交机构独立的第三名复核者仲裁。
10. 只有三条审校线都达到门槛、来源宇宙相关空白已处理且证据冻结后，才可产生分母变更提案。

单份 Issue、单个模型输出、单一机构内部决定或未经签名的批量表格都不会自动改变分母。

### 6.1 审校账本的持久记录格式

`global-denominator-review-ledger-v0.1.0.json` 同时是构建输入和公开账本，不是每次构建都可清空的临时产物。构建器先读取并验证已有的 `reviewerDeclarations`、`decisions` 与 `arbitrations`，再重算摘要；格式或引用无效时立即失败，不会用空数组覆盖记录。历史 v6.18 发行仍冻结在零决定状态；一旦出现第一项合格决定，必须发布新的 GBCR 版本，不得原地改写 v6.18。

复核者声明至少包含：唯一 `reviewerId`、`naturalPerson: true`、`aiSystem: false`、非空 `competence`、首次机构声明 `institution`、版本化 `affiliations`、利益冲突说明 `conflictOfInterest`、可验证 `signature`、原始 `sourceIssueUrl`、独立 GitHub 验收者与验收时间。每次机构变化记录机构、来源 Issue、候选哈希、验收者与时间。每项决定至少包含：唯一 `decisionId`、有效 `queueId` 与 `reviewerId`、`independent: true`、审校线 `lane`、该线允许的决定字段、ISO `submittedAt`、非空 `rationale`、至少一个 HTTPS `evidenceUrls`、候选 `submissionSha256`、本次提交的能力、机构、利益冲突、来源范围与支持证据快照、原始 Issue 和独立验收记录。相同复核者不得在同一任务同一审校线重复投票；自动共识和仲裁的机构独立性按决定快照判断。仲裁必须引用至少两项既有且有实质分歧的决定，并包含同等来源、哈希、独立性、提交及验收字段；仲裁者必须由人员与机构均独立于原复核者的自然人签署。所有数组只追加；纠错用新记录和新版本表达，不覆写旧记录。

## 7. 仲裁与纠错

第三方仲裁者不得是原两名复核者，也应避免相同利益冲突。仲裁记录必须逐项引用双方证据，说明采纳与不采纳理由，并允许给出“仍未决”。所有历史决定只追加、不覆写；如新写本、校勘或研究推翻旧决定，以新版本追加更正并保留旧哈希。

## 8. 保守分母与覆盖率

保守分母：

```text
已批准纳入且身份冻结的独立作品
+ 尚未归入冻结作品的未决候选记录
+ 经复核的已知缺失作品占位
```

某一维度的分子：

```text
在相同冻结分母中，已批准纳入、身份冻结，
且满足该单独维度规则的作品
```

保守下界：

```text
dimension_numerator / conservative_denominator
```

只有 G0–G6 全部通过，并且某一单独维度的保守下界不低于 99%，才能发布该维度的 99% 声明。不得从其中一个维度推导其他维度，也不得以平均值掩盖缺口。

## 9. G0–G7 发布门

- G0：术语与范围政策完成；
- G1：全球主要传统、语种、写本与地区来源宇宙完成独立审计；
- G2：每条候选记录映射到作品表达/见证、未决记录或排除证据；
- G3：作品范围完成独立双重复核；
- G4：作品身份完成独立双重复核，分歧完成第三方仲裁；
- G5：权利、全文、翻译与质量分子分别可复算；
- G6：分母版本、输入哈希、未决项和已知缺失项同时冻结；
- G7：仅对达到 99% 保守下界的单独维度发布声明。

## 10. 长期保存

标准、来源宇宙、队列、账本、Issue 摄取候选、原始意见、仲裁记录、构建脚本、登记册和校验和必须进入 Git 历史与不可变保存包。每次发布都记录完整输入路径、SHA-256、版本和生成脚本。未来格式迁移不得删除旧版本，也不得重写历史裁决。
