# foxue.ai 汉—巴作品关系复核协议

本协议规定 `data/gbcr/suttacentral-parallel-review-queue-v0.1.0.json` 中 80 项未决关系如何接收真人复核、处理分歧并形成可追踪裁决。目标不是尽快减少 Work 数，而是让每一次作品边界变更都能被下一代复算、反驳和撤销。

## 1. 三条不可越过的边界

1. 队列项只是候选关系，不是“同一作品”的结论。
2. AI 可以检索、转写、生成比对草稿和整理参考文献，但不能作为真人复核者署名、投票或满足双人门槛。
3. 未完成两份合格的独立复核与必要仲裁前，不得合并 Work、断言逐段等同或改变全球佛典分母。

## 2. 谁可以提交复核

任何人都可提交可复核证据。要被计入正式独立复核，提交者须：

- 使用可长期追踪的 GitHub 身份署名；可附 ORCID 或机构，但不要求公开私人邮箱；
- 说明能直接核对哪些语言与版本；依赖译文时必须明确译文来源；
- 披露与项目、文本版本、翻译、出版或另一位复核者的利益关系；
- 独立阅读证据后形成结论，不能复制另一位复核者的判断来满足人数；
- 同时记录支持证据和反证，不能只列有利材料。

自动代理、匿名模型输出、批量生成但无人负责的意见和只根据题名或编号作出的判断，可以作为线索，但不计为真人复核。

## 3. 每份复核必须回答的问题

### 3.1 文本身份与范围

- 两端是整经、合集内部组件、选段、残片、节译、改写还是引用？
- 使用的底本、版本、经号、卷页、段落范围和稳定链接是什么？
- 题名、目录层级或编号是否存在一对多、多对一或后期重编情况？

### 3.2 文本内部证据

- 开头、结尾、说法地点、人物和叙事框架是否相合？
- 章节结构、教义次序、重复模式和核心譬喻如何对应？
- 有哪些显著增文、删文、移位、异本或只在一端出现的材料？
- 上游 `remark` 与 `resembling` 标记是否被正文支持？

### 3.3 外部证据与反证

- 至少引用一项可公开核对的现代研究、权威目录或校勘成果；若没有，应选择“证据不足，保持未决”；
- 明确写出最强支持证据与最强反证；
- 区分“历史上相关”“同一文本家族”“同一作品的不同表达”和“逐段等同”。

### 3.4 权利与可持续性

- 分别说明原文、转写、译文和元数据是否允许长期保存、公开链接与再分发；
- 不能把某一译文的许可扩大为原文或其他译文的许可；
- 引用受限来源时，只记录必要引文、书目信息、稳定定位和权利边界。

## 4. 允许的复核结论

| 代码 | 含义 | 是否立即改变 Work 数 |
|---|---|---:|
| `same_work_different_expression` | 同一规范作品的不同语言或版本表达 | 否；待第二复核与裁决 |
| `text_family_relation_only` | 同属文本家族，但作品边界不能归一 | 否 |
| `component_relation_only` | 一端只是另一登记作品内部组件 | 否 |
| `partial_parallel_only` | 只有局部或结构性平行 | 否 |
| `citation_or_mention_only` | 引用、提及或短片段关系 | 否 |
| `rejected_not_parallel` | 证据不足以维持平行关系 | 否；待第二复核与裁决 |
| `unresolved_more_evidence_required` | 尚不能判断 | 否 |

任何单份复核都不直接改变登记册。

## 5. 独立性、分歧与仲裁

- 两位复核者不得共同撰写后拆成两份意见，也不得由同一人控制的多个账户提交；
- 第二位复核者可以阅读第一份意见，但必须说明是否先独立形成过初步判断，并逐项回应关键证据；
- 两份结论一致时，仍需由维护者检查字段完整性、引用可访问性、权利边界和证据范围；
- 两份结论不一致，或虽然代码一致但作品范围不同，必须由第三位具名仲裁者处理；
- 仲裁者必须解释为何采纳、组合或拒绝既有意见，不能只投票；
- 复核者、仲裁者或维护者存在利益冲突时，应回避相应决定。

## 6. 从意见到登记册变更

1. 复核者通过 GitHub 的“汉—巴作品关系复核”表单提交结构化意见。
2. 维护者只先检查完整性与可复核性，不把“格式合格”解释为“学术结论正确”。
3. 合格意见以原始 GitHub 链接、提交者身份、时间和内容哈希进入版本化复核账本；后续修订不得抹去旧意见。
4. 满足双人门槛后，由独立裁决提交提出 Work/Expression/Witness 变更、迁移影响、稳定链接兼容和反向撤销方案。
5. 自动校验检查作品数、表达数、关系边、全球分母、段落 ID、来源哈希和权利状态；任何未解释漂移都会让构建失败。
6. 变更经代码审查、全站测试、保存包和生产验证后进入新 GBCR 版本。旧登记册永久保留。

## 7. 修订、撤回与异议

- 复核者可追加更正，但原意见和时间线必须保留；
- 发现引用失效、版本误认、利益冲突或身份冒用时，任何人都可提交异议；
- 已裁决关系若出现更强反证，应新建反向裁决，不能静默改写历史；
- 回滚作品合并时须保留旧稳定链接的解析或迁移记录，避免破坏长期引用。
